# Session 對話整理

將目前對話及其 subagent sessions 整理成繁體中文 Markdown 筆記，保存於目前專案根目錄的 `session/`。筆記應讓稍後回來的使用者或 Agent 能快速掌握背景並接續工作，不要逐字重播對話。

## 步驟

1. 回顧目前 session，擷取目標、背景、已確認需求、重要決策及其理由、已完成工作、涉及檔案、驗證結果、未解問題與下一步。保留仍有效的細節，區分已確認事實、暫定想法與未決事項。
2. 找出目前 session 所屬的 subagent sessions，讀取其可用對話內容並納入整理。依 session 關聯資料辨識子 session，遞迴檢查其中啟動的 subagent sessions；只整理屬於目前 session 工作脈絡的內容。可從 OpenCode session 儲存資料中檢視 session metadata 與訊息記錄；先確認實際資料位置及格式，再讀取，不假設固定平台路徑。若無法取得某個子 session，記錄其識別資訊及無法讀取的原因，不將未讀內容當作已整理。
3. 整合主 session 與 subagent 的發現，去除重複內容，保留重要結論、決策、理由、執行成果及未完成事項；需要時標明由哪個 subagent 提供，以及是否已由檔案、規格、票單、提交或差異驗證。若 subagent 結論彼此不一致，保留分歧並標示待確認，不自行抹平。
4. 查看專案目前狀態及可用的相關產物；以檔案、規格、票單、提交或差異作為權威來源。摘要引用這些產物即可，不複製其完整內容，也不把未驗證的推測寫成事實。
5. 在專案根目錄的 `session/` 建立 Markdown 檔。若目錄不存在則建立。使用 `YYYY-MM-DD-<簡短主題>.md` 作為檔名；若檔名已存在，改用不覆蓋既有內容的唯一檔名。
6. 檢查筆記涵蓋下列各節；沒有內容的項目寫「無」，不適用的項目可略過：

   - 摘要與目標
   - 背景與需求
   - 決策與理由
   - 已完成工作與變更檔案
   - 驗證結果
   - 未決問題／風險
   - 下一步（依優先順序）
   - 相關參照（專案內路徑、提交或連結）

7. 遮蔽 API key、密碼、token 等機密值；只記錄接續工作所需的資訊。完成後回報檔案路徑、摘要涵蓋的主 session 與 subagent sessions，以及任何無法讀取的 session。

## 完成條件

筆記已寫入 `session/`，內容涵蓋目前主 session 與可取得的相關 subagent sessions，可讓未讀取原對話的後續工作者辨識目前狀態、權威參照與明確的下一步；無法取得的 sessions 已明確揭露，機密資訊已遮蔽。
