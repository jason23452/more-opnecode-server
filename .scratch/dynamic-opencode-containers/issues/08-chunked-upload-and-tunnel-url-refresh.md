# 08: 分塊重試並刷新 Tunnel 上傳目標

**What to build:** 讓大型專案以多個可重試區塊直接經容器 Tunnel 傳送；Tunnel URL 改變時 CLI 可取得最新目標並繼續上傳，只有完整專案驗證成功後才更新工作目錄。

**Blocked by:** 07: 透過容器 Tunnel 直接上傳專案.

**Status:** resolved

- [x] CLI 將專案封裝切成小於 Tunnel 單次請求上限的區塊，並透過目標容器 Tunnel 直接傳送；檔案區塊不經管理後端。
- [x] 容器端建立隔離的暫存上傳工作階段，支援區塊索引/完整性驗證與安全重送；缺漏、重複或損壞區塊不可破壞目前工作目錄。
- [x] 所有區塊與封裝驗證成功後，接收器才原子安裝新的專案工作目錄；失敗或中斷時保留舊專案，並清理可回收的暫存資料。
- [x] 提供以容器專屬 upload token 驗證的控制 API，僅回傳最新 Tunnel upload URL，不接收專案檔案內容。
- [x] CLI 遇到 Tunnel URL 過期或連線失敗時刷新目標並重試未完成區塊，完成後仍只連線至該容器。
- [x] 以超過單次請求上限的專案及 Tunnel URL 改變情境驗證重試、隔離、完整性及工作目錄原子更新；Docker/Quick Tunnel E2E 已使用 96 MiB 封裝與失效起始 URL 驗證刷新續傳及完整安裝。
