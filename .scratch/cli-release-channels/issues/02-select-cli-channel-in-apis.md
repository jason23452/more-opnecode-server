# 02: 讓所有 CLI 安裝資訊 API 依 prod／dev 通道選版

Status: ready-for-agent

**所屬規格：** CLI prod／dev 發布與下載通道隔離（cli-release-channels）

**What to build:** 管理者透過任一提供 CLI 安裝／下載資訊的 API 取得指令時，都依後端通道設定使用同一套 Release 選版規則。prod 僅下載正式 CLI，dev 僅下載開發 CLI；來源失敗時明確報錯，不跨通道回退。

**Blocked by:** 無，可立即開始；以模擬 Release 資料驗證，不需等待 01 發布真實資產。

## 驗收條件

- [x] 新增 `OPENCODE_CLI_CHANNEL`，僅允許 `prod`、`dev`，未設定預設為 `prod`，非法值於載入設定時拒絕。
- [x] prod 僅選 `cli-v*` 且非 Pre-release 的 Release；dev 僅選 `cli-dev-*`，接受開發版 Pre-release；兩者均排除草稿、尚未發布與缺少必要資產的版本。
- [x] 必要資產包含四平台執行檔與兩種安裝腳本，與既有發布資產名稱一致。
- [x] 依 `published_at` 選取最新符合條件的版本，同時發布時以 Release ID 固定排序；處理分頁，不因第一頁無匹配版本而誤判，也不以 tag 字串或通用 Latest 端點選版。
- [x] 共用選版結果套用到獨立 CLI 安裝指令 API、建立容器回應的 `cli_install_commands` 及盤點發現的其他安裝／下載資訊入口。
- [x] Windows、macOS、Linux 安裝指令中的安裝腳本與執行檔來源固定至同一個 tag，維持既有成功回應欄位及平台參數。
- [x] 移除 `OPENCODE_CLI_RELEASE_URL` 在安裝指令選版路徑的任意覆寫能力，舊設定不會繞過通道限制；更新相關程式與測試。
- [x] GitHub 查詢具有有限逾時與依通道隔離的快取，快取期限不超過 60 秒；到期後重新查詢，失敗不使用過期結果。
- [x] 無可用版本、GitHub 逾時、限流或服務錯誤回傳 `503` 及可理解的錯誤，不回退至其他通道。
- [x] 建立容器前先確認可取得所需 Release；選版失敗不建立容器。管理 token 驗證、容器連線指令與上傳指令的既有契約維持有效。
- [x] API 測試覆蓋兩通道、所有平台、預設與非法設定；混合資料中即使另一通道版本較新，仍只選本通道。
- [x] 測試覆蓋發布時間排序、同時發布、分頁、草稿、資產不完整、正式通道排除 Pre-release、查無版本及 GitHub 錯誤。
- [x] 以可控制時間與模擬 GitHub 回應驗證快取隔離、有效期間重用、到期取得新版本及失敗行為，並驗證未授權請求與選版失敗無容器副作用。
- [x] 沿用安裝腳本測試，確認版本化下載來源可供現有安裝腳本使用；必要後端與 CLI 回歸測試通過。

## 測試與交付說明

主要測試邊界為現有後端 API，以可替換的 GitHub 查詢邊界模擬外部資料，驗證回應與副作用，不綁定內部函式拆分或呼叫次數。測試不得依賴即時 GitHub 網路或真實發布；設定範例與 Compose、本機環境的接線由 03 整合。
